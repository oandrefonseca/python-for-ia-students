26  Recursão

Uma função recursiva resolve um problema chamando a si mesma sobre um caso menor, até atingir um caso base. Toda recursão consome a pilha de chamadas — ligação direta com o próximo capítulo.

26.1 Anatomia

def fatorial(n: int) -> int:
    if n <= 1:                       # caso base: onde a recursão para
        return 1
    return n * fatorial(n - 1)       # passo recursivo: problema menor

Sem caso base (ou sem convergir para ele), a recursão não termina e o Python interrompe com RecursionError ao estourar o limite de profundidade (~1000 chamadas; ajustável com sys.setrecursionlimit, com cautela).

26.2 O custo da recursão ingênua

# Fibonacci ingênuo: O(2ⁿ) — recalcula os mesmos valores muitas vezes
def fib(n: int) -> int:
    return n if n < 2 else fib(n - 1) + fib(n - 2)

fib(35) já leva segundos: a árvore de chamadas explode exponencialmente.

26.3 Memoização: de O(2ⁿ) para O(n)

Guardar resultados já calculados elimina o retrabalho — e o decorator lru_cache (Capítulo 18) faz isso em uma linha:

from functools import lru_cache

@lru_cache(maxsize=None)
def fib_rapido(n: int) -> int:
    return n if n < 2 else fib_rapido(n - 1) + fib_rapido(n - 2)

fib_rapido(500)      # instantâneo

26.4 Recursivo × iterativo

Todo algoritmo recursivo tem versão iterativa (às vezes usando uma pilha explícita — Capítulo 28). A iterativa evita o limite de profundidade; a recursiva costuma ser mais legível quando o problema é naturalmente recursivo:

def fatorial_iterativo(n: int) -> int:
    resultado = 1
    for i in range(2, n + 1):
        resultado *= i
    return resultado

26.5 Onde a recursão brilha

Em estruturas naturalmente recursivas: uma árvore é um nó com subárvores; percorrê-la recursivamente é quase transcrever a definição (Capítulo 31). O DFS em grafos (Capítulo 32) segue o mesmo princípio.
